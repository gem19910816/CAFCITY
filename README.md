# CAF 失落城市自定义城市附属

本项目是 Minecraft 1.21.1 / NeoForge 的 Lost Cities 附属模组。它为不同距离阶段的城市加载自定义建筑、分区与道路 NBT，并调整 Lost Cities 的城市选址、地基和建筑生成流程。

本文面向接手项目的开发者，也适合交给另一个 AI 继续维护。请以当前源码和游戏实例中的 `config/CAF失落城市配置/城市风格配置.json` 为准；本文件的当前交付版本为 1.0.216（2026-11-07）。用户配置会随着测试继续变化，提交代码前先检查配置与工作区状态。

- 此为新世界交付。小镇全局计划改变；已生成区块不搬迁、不修旧存档，既有上限也不等于所有地形都必定凑齐下限。验证入口与限制见[1.0.214验证说明](验证说明-1.0.214.md)。

## 1.0.213：生存城市勘察图

- 新增 `caf_lc_customcity:city_survey_map`，2张纸和1个木炭无序合成，背包2×2格即可制作，可重复使用且不消耗。普通生存玩家无需OP即可使用；原管理员命令权限保持不变。
- 主世界主手拿图，默认选择T1；潜行右键在T1乡村、T2小镇、T3小城、T4大城之间循环，松开潜行右键查询该等级最近的真实规划城心。T0是城市外的野外，不存在T0城。每次查询间隔10秒。
- 查询复用生成使用的全局城市计划，支持尚未探索的规划城市；回复中文方向、水平直线距离和可点击复制的XZ坐标，不传送、不揭开地图、不请求目的地区块生成。定位高阶城市不授予科技阶段，也不判断道路、水域、入口与路线安全。
- 查询时副手拿普通指南针，结果返回时仍持有同一支指南针，才标定城心目标。使用1.21.1 `LODESTONE_TRACKER`、`tracked=false`，无需放置磁石。查询期间更换指南针不会改写替换品的原目标；没有合格城市、查询失败或配置已变更时保留原目标。
- 城市查询采用每服务器独立的单线程后台会话、固定规划视图与单飞限制。服务器停止时标记会话失效并中断执行器；过期会话、离线、换维度与配置修订后的回复不会修改玩家指南针。玩家消息和组件修改均回到服务器线程；固定视图不追随Lost Cities生成时可变的WorldGenRegion，不提供可变feature与区块访问。
- 本版本没有执行Minecraft实机交互验收。源码检查、离线构建及生命周期守卫不能代替新物品注册、使用动画、指南针网络同步与查询中退出世界的游戏测试。

## 游戏内指令

以下指令要求 OP 权限等级 2。命令注册失败时会记日志，但不应阻止游戏启动。

| 指令 | 用途 |
|---|---|
| `/cafcity`、`/cafcity nearest` | 搜索当前位置附近最近的城市，默认搜索范围 5000 格。结果包括城心、阶段、风格、距离和出生点距离等信息。 |
| `/cafcity <距离>`、`/cafcity nearest <距离>` | 指定最近城市搜索范围，例如 `/cafcity 10000`。 |
| `/cafcity inspect` | 检查当前位置属于哪个阶段生成范围、是否在城市中、所在风格和分区；若当前区块有附属建筑，会显示建筑资产 ID 和对应的源 `.nbt` 文件名。 |
| `/cafcity find <阶段> <风格> [距离]` | 搜索指定阶段和风格的城市；省略距离时使用命令允许的最大搜索范围。例：`/cafcity find 乡村 西式风格 10000`。阶段名和风格名需是单个 Brigadier 单词，不能含空格。 |
| `/cafcity all` | 搜索当前位置 20000 格范围内的城市，返回各城阶段、风格和城心坐标。范围较大，执行期间可能需要等待。 |
| `/cafbuildstats` | 汇总并导出建筑生成统计，在聊天栏返回导出文件路径。 |

城市搜索结果中的坐标可点击，用来把坐标填入传送命令；Y 坐标采用城市地面高度。点击只填充命令，不会直接传送。

## 配置目录

配置根目录为实例的 `config/CAF失落城市配置/`。启动时会按根配置声明创建风格、阶段和分区目录骨架；即使某阶段禁用，也会为配置中存在的阶段创建目录。不要把旧版 `config/失落城市建筑/`、内城/外城配置或旧的道路方块比例逻辑当作当前配置入口。

```text
CAF失落城市配置/
├─ 城市风格配置.json             # 唯一的主要配置入口
├─ 城市配置总览.json             # 自动生成的只读概览
└─ 西式风格/                     # 名称必须列在“可用城市风格文件夹”中
   └─ 乡村/                      # 阶段名，必须与根配置一致
      ├─ 道路文件/
      │  ├─ 直道/*.nbt
      │  ├─ 弯道/*.nbt
      │  ├─ 尽头/*.nbt
      │  ├─ 三岔路口/*.nbt
      │  └─ 十字路口/*.nbt
      └─ 乡村/                   # 分区名；每个分区一个同名目录
         ├─ 建筑文件/*.nbt
         └─ 战利品文件/*.json
```

道路目录位于风格/阶段下，不按分区分别选择。每个道路 `.nbt` 是完整道路场景。启动扫描道路文件后，根配置中对应阶段的 `道路生成权重` 会按 `形状/文件名.nbt` 自动补齐；权重控制同形状道路变种之间的相对抽取比例。阶段使用的道路宽度以根配置为准。

分区建筑放在 `风格/阶段/分区/建筑文件/`。支持 `.nbt`，项目也保留 `.schem` 导入兼容。游戏已启动后替换文件，应完全退出再启动以触发扫描和建筑包重建。

战利品 JSON 的物品格式示例：

```json
{
  "战利品池": {
    "物品": [
      { "物品": "minecraft:bread", "最少数量": 1, "最多数量": 3, "权重": 5 }
    ]
  }
}
```

当前阶段/分区读取的覆盖优先级是“建筑文件名对应的战利品 JSON > 分区通用 JSON”。例如 `商店.nbt.json` 覆盖该建筑，`分区通用.json` 用于该分区其余建筑。物品 ID 是注册名；数量范围含上下限，权重越大越容易抽到。战利品尚未充分实测，暂不要承诺全城通用表、建筑原箱内容和各类容器均符合预期。

## 根配置说明

主配置：`城市风格配置.json`。本节描述当前生成模板和解析代码使用的键；缺失字段通常回落内置默认值，`null` 表示不限制/不指定的字段除外。修改后重启游戏。

### 根级字段

| 字段 | 功能 |
|---|---|
| `可用城市风格文件夹` | 风格白名单。每个名字对应配置根目录下的单层目录；缺失目录会在启动时创建。目录存在只表示它是可选风格，不保证其中有可用建筑；固定风格阶段还会检查对应阶段是否能扫描到建筑文件。 |
| `允许生成的群系` | 城市中心允许生成的群系注册名列表，例如 `minecraft:plains`。列表外不生成阶段城市；列表为空或包含 `*` 时不限制群系。 |
| `城市地面高度最小` / `城市地面高度最大` | 阶段城市中心所处地形高度允许范围，单位为方块 Y。限制是中心选址条件，不代表城市边缘地形不会有落差。 |
| `城市风格分配方式` | `按阶段配置` 使用每个阶段的 `城市风格`；`所有城市随机` 按每座城市位置稳定抽风格；`按阶段随机` 为每个阶段选风格。随机模式只从可用且在该阶段启用的风格中选择。 |
| `相邻阶段允许相同风格` | 按阶段随机时，控制相邻阶段是否允许抽到同一风格。仅有一个可用风格时仍会复用。 |
| `城市风格生成概率` | 风格权重对象。权重越大，在随机风格模式下被选中的相对概率越高；这是权重而非百分比，未填写的风格权重为 1，0 表示不参与抽取。 |
| `阶段数量` | 阶段数，最多 10。应与 `阶段` 中配置的阶段数量和名称对应；阶段目录名称也使用这里的阶段名。 |
| `风格阶段生成` | 按“风格 → 阶段”配置启用、城市数配额和生成概率，见下表。随机风格模式下需要为目标风格/阶段设置有效规则。 |
| `附属功能设置` | 影响所有阶段城市的附属选项，详见下表。 |
| `城市生成配置` | 覆盖 Lost Cities 配置档参数，见后文完整字段说明。 |
| `阶段` | 每个阶段独立设置距离范围、开关、分区、道路和生成规则，见后文。 |

`风格阶段生成.<风格>.<阶段>` 下字段：

| 字段 | 功能 |
|---|---|
| `是否生成` | 是否允许这个风格的这个阶段出现。关闭后不会由该阶段生成此风格。 |
| `生成数量下限` / `生成数量上限` | 候选城心扫描区域内此风格/阶段的城市数量配额边界；上限可省略表示不设上限。候选数超过上限时，程序按世界种子稳定抽取一个上下限之间的目标数，再截取候选；候选数不足下限时不会创造中心。它不是单个城市半径内的建筑数量。 |
| `生成概率` | 此风格/阶段候选城市通过概率检查的概率，0 到 1。 |

阶段启用有两道门槛：`阶段.<阶段名>.启用` 和 `风格阶段生成.<风格>.<阶段>.是否生成` 都要开启。固定风格模式还要求 `城市风格` 指向的风格已列入 `可用城市风格文件夹`，并且该风格阶段目录下至少能扫描到建筑文件。只创建了目录或只打开其中一个开关，都不会让阶段城市出现。

结构示例（仅展示层级，数值需按测试设计调整）：

```json
{
  "可用城市风格文件夹": ["西式风格"],
  "城市风格分配方式": "按阶段配置",
  "风格阶段生成": {
    "西式风格": {
      "乡村": {
        "是否生成": true,
        "生成数量下限": 0,
        "生成数量上限": 20,
        "生成概率": 1.0
      }
    }
  },
  "阶段": {
    "乡村": {
      "启用": true,
      "距离最小": 0,
      "距离最大": 3000,
      "城市风格": "西式风格",
      "使用分区": true
    }
  }
}
```

这只是局部示例。真实配置还应有 `阶段.乡村.生成规则`、分区、道路设置和 `城市生成配置` 等字段；读取器通常会补缺省字段，但不要把片段直接覆盖完整配置文件。

`附属功能设置` 下字段：

| 字段 | 功能 |
|---|---|
| `出生点城市中心距离` | 保证出生点附近存在城市中心的搜索距离，单位格；0 关闭。它会寻找规则允许的位置，不表示强制把城心放在精确距离圆周上。 |
| `生成建筑自带的动态结构` | 是否恢复建筑 NBT 中导出的实体/动态结构数据，例如机械动力结构相关实体。机械动力结构仍需实机验证。 |

### 阶段配置

`阶段.<阶段名>` 下的字段：

| 字段 | 功能 |
|---|---|
| `启用` | 开启/关闭该距离阶段。关闭阶段后，其范围内不会生成阶段城市。 |
| `距离最小` / `距离最大` | 阶段距出生点的距离区间，单位格；最大值为 `-1` 表示无限。边界按源码实现的半开区间判断。 |
| `城市风格` | 固定风格模式下使用的风格目录名。 |
| `使用分区` | 是否用该阶段的分区布局划分城市。关闭时走该阶段可用的非分区布局路径。 |
| `道路` | 阶段道路宽度与道路变种权重，见下表。 |
| `分区` | 一个或多个命名分区定义，字段说明见下表。 |
| `生成规则` | 该阶段自己的城心、城市半径、建筑布局和逐建筑生成规则。 |

`阶段.<阶段名>.道路`：

| 字段 | 功能 |
|---|---|
| `道路宽度` | 此阶段使用的道路区块宽度；一个阶段只采用一种宽度。 |
| `道路生成权重` | 启动扫描得到的 `形状/文件名.nbt: 权重`。同一种道路形状的候选变种按权重抽取；正权重之间按比例抽取。新增/删除道路文件后会重新扫描。 |

例如：

```json
"道路生成权重": {
  "直道/直路1.nbt": 8.0,
  "直道/直路2.nbt": 1.0
}
```

该例仅影响 `直道` 这一形状；`弯道`、`三岔路口` 等形状有各自独立的一组候选和权重。权重 8:1 表示相对机会，不保证每九次严格出现八次。所有候选权重为 0 时，运行时会退回在候选文件中确定性选择，因此要禁用某个形状，应移走该形状下所有 `.nbt`，而不是只把它们的权重都设成 0。

`阶段.<阶段名>.生成规则.城市`：

| 字段 | 功能 |
|---|---|
| `最小半径` / `最大半径` | 阶段城市半径范围，单位格。 |
| `城心生成概率` | 候选位置成为城市中心的概率，0 到 1。 |
| `候选城心数量` | 每个候选网格/扫描批次中评估的候选中心数量。 |
| `候选网格大小` | 城心候选网格尺寸，单位格；影响选址采样范围与密度。 |
| `城心附近地形检查` | 是否在候选城心周边检查群系/高度等适配条件。 |
| `城心附近地形检查半径` | 周边地形检查半径，单位格。 |
| `城心间隔.最小` / `城心间隔.最大` | 同阶段城市中心之间允许的距离范围，单位格；`null` 表示该端不限制。城市半径避让也由生成逻辑参与计算。 |

`阶段.<阶段名>.生成规则.建筑布局`：

| 字段 | 功能 |
|---|---|
| `建筑间隔.最小` / `建筑间隔.最大` | 建筑/道路网格布局的间距范围，单位区块。`null` 表示由阶段道路宽度推导默认间距；数值 0 表示允许相邻。 |
| `连续生成最大宽度` / `连续生成最大长度` | 连排建筑组的横向宽度和纵向长度上限，单位区块；源码会保证长度不小于宽度。 |
| `相同建筑间隔` | 同一建筑文件再次生成前需要的间隔，单位区块。 |

`阶段.<阶段名>.生成规则.建筑.<建筑文件名>` 对每个扫描到的建筑文件自动建立一项：

| 字段 | 功能 |
|---|---|
| `生成间隔.最小` / `生成间隔.最大` | 该建筑与同种建筑之间的独立间隔覆盖，单位区块；两端都为 `null` 时使用阶段级 `相同建筑间隔`。 |
| `刷新率` | 该建筑在符合布局条件时的相对生成概率，0 到 1。 |
| `最少数量` | 每座城市的布局中该建筑应达到的数量下限。只有地图内有足够符合占地/间距要求的位置时才能达到。 |
| `最大数量` | 每座城市布局中的数量上限；`null` 表示不限制。 |

### 分区配置

每个 `阶段.<阶段名>.分区.<分区名>` 是一个独立区域。新增分区后，会按分区名称创建建筑和战利品目录。

| 字段 | 功能 |
|---|---|
| `启用` | 是否参与该阶段城市布局。 |
| `形状` | 区域几何形状，如圆形、环形、扇形、矩形；具体可用值以 `StagePartitionConfig`/布局解析代码为准。 |
| `摆放方式` | `固定` 按给定中心/角度摆放；随机方式在城市内选择位置。 |
| `优先级` | 分区覆盖重叠或分区间空隙归属的优先顺序，数字越大优先级越高；相同优先级按布局实现处理。 |
| `大小.中心X` / `大小.中心Z` | 相对城市中心的分区中心偏移，单位区块。 |
| `大小.内半径` / `大小.外半径` | 环形/圆形区域内外半径，单位区块。 |
| `大小.宽度` / `大小.长度` | 矩形区域宽和长，单位区块。 |
| `大小.角度起点` / `大小.角度范围` | 扇形起始角和角度范围；角度 0 朝南、90 朝东、180 朝北、270 朝西。 |
| `建筑布局.建筑间隔.最小` / `最大` | 分区覆盖阶段默认建筑间距；`null` 时按阶段道路宽度推导，0 允许相邻。 |
| `建筑布局.并排生成最大宽度` / `最大长度` | 分区连排组的最大宽度/长度，单位区块；长度不得小于宽度。 |
| `建筑布局.连排建筑生成概率` | 满足尺寸和间隔条件时尝试生成连排组的概率，0 到 1。 |
| `建筑布局.空地也要放建筑` | 是否尽量将该分区的可用空地继续填入建筑。 |
| `建筑布局.大楼之间强制留一格空隙` | 是否要求大型多区块建筑间额外留出一个区块。 |

默认模板中常见的 `住宅区`、`工业区`、`商业区` 只是初始分区示例。阶段和分区都可以按配置改名；目录名必须与配置名一致。

分区大小单位以“区块”为准，1 区块 = 16×16 格。比如圆形分区半径 10 区块，半径约为 160 格。分区之间可重叠；重叠区由优先级和分区规划器决定归属。没有被任何明确分区覆盖的空缺会参考相邻分区处理，不应假设分区之间会自动补成某个固定默认区。

分区中建筑文件应放进配置名完全相同的目录，例如 `西式风格/乡村/乡村/建筑文件/`。改变分区名后，旧目录不会自动改名或迁移，须自行移动建筑和战利品文件。根目录的 `城市配置总览.json` 只用于核对阶段与分区名称，编辑它不会改变运行时配置。

## 生成流程

### 启动时

1. 读取 `城市风格配置.json`，校验阶段、可用风格和分区配置。遇到缺项使用默认值，JSON 错误会写日志；不要仅凭目录已创建就认为该风格有效。
2. 创建配置指定的风格/阶段、分区建筑/战利品目录和阶段道路形状目录。此过程只创建缺少的目录，不会生成用户的建筑 NBT。
3. 扫描启用风格与阶段目录中的建筑文件，识别文件所属分区，转换为 Lost Cities 使用的 `parts`、`buildings` 和 `multibuildings` 等数据资源。逐建筑规则按源文件名关联。
4. 扫描阶段道路目录中的 `.nbt` 并补齐道路权重表；读取战利品 JSON 并附加到对应建筑资源。
5. 将生成的数据作为附属数据资源注入启动流程。更改 NBT 或根配置后要完整重启游戏，已生成区块不会因此重新运行生成流程。

### 城心选择

阶段系统将出生点到候选中心的水平距离用于选择阶段。距离按 X/Z 平面计算，不使用 Y 高差；阶段距离区间的最大端不包含在区间内。每阶段的候选采样是确定性的：世界种子、阶段名和候选网格坐标决定候选点，因此同一世界重新打开时不会随机漂移。

当前模板的候选网格大小为 1024 格、每个网格尝试 10 个候选点。网格只是采样单位，不是城市边界，也不保证网格里一定有城。候选点会对齐区块，并在其周边最多 4 个区块范围内寻找最近的合格地形，避免一个点落在海岸/陡崖上就直接丢掉附近可用地形。随后还要通过以下检查：

- 阶段已启用，且候选中心到世界出生点的距离落在该阶段范围内。
- 风格可用，且该风格/阶段在 `风格阶段生成` 中启用；生成概率通过确定性概率抽取。
- 中心群系属于根级 `允许生成的群系`，世界表面高度在根级高度范围内。
- 启用了 `城心附近地形检查` 时，以配置半径对周边地形作粗采样；检查使用区块级步长，不是逐方块扫描。
- 候选城市之间通过配置的中心间距筛选。最小间距约束会优先保留由世界种子确定的候选；最大间距若有设置，则用于限制候选必须靠近已有中心的距离关系。设置最大值时需同时留意最小值，否则候选可能因没有满足距离窗口的邻城而被过滤。
- 对通过检查的候选，再应用风格/阶段的生成数量上限。数量下限只能在候选城市已经足够时保留目标数量，不能从不合格地形或不存在的候选点“造出”城市。

出生点保证城市是额外路径：`出生点城市中心距离` 设为正数时，先检查该距离内是否已有城市中心；若没有，尝试从配置规则允许的位置中找一个最近的合格中心，并把它作为合成城市加入城市生成。它不把城市固定在精确距离圆周上，也不绕过城市间距和地形要求。指令搜索结果中的“计划城心”是算法认为的城心；必须继续传送并观察实际地皮，才能确认该区域已正常生成。

### 城市地块与建筑

城心通过 Lost Cities 的城市范围判断后，附属按城市坐标规划区块地块，并把分区映射到这些地块。道路和建筑最终都按区块落位。阶段道路宽度会参与默认建筑间距；显式填写间距会覆盖默认值。每对相邻建筑的有效间距同时受两栋建筑的规则约束，不能只看其中一栋的设置。

逐建筑配置中的 `最少数量` 大于 0 时，布局规划会优先为这座城市预留位置；`最少数量` 为 0 时表示可选，不会暗中提升为至少生成一栋。剩余空地再根据 `空地也要放建筑`、刷新率、面积、分区、间距、最大数量等条件填充。大面积多区块建筑会优先占用更大地块，因此可用地块不足或相同建筑间隔过严时，配置中的最少数量未必能全部实现；日志和游戏内实测都要核对。

连排建筑需要源 NBT 的占地形状适配连续矩形布局。系统尝试在候选空地上组出完整矩形，不能形成完整矩形的 L/T 形组合会被拒绝。`并排生成最大宽度` 是组的短边上限，`最大长度` 是长边上限；配置和布局都要求长边不小于宽边。连排生成概率控制建立一组连续建筑的尝试；它不会让单栋建筑绕过占地和间距检查。当前代码还会按组的轴向和源建筑南门基准调整朝向，必须用两种轴向、不同占地宽深的 NBT 进行游戏验收。

### 道路 NBT

道路形状由 Lost Cities 当前道路区块的连接关系决定：

| 形状目录 | 对应连接 |
|---|---|
| `直道` | 两端连接，形成直线段。 |
| `弯道` | 两个相邻方向连接，形成 90 度转弯。 |
| `尽头` | 仅一端连接，另一端封口。 |
| `三岔路口` | 三个方向连接。 |
| `十字路口` | 四个方向全部连接。 |

形状目录下可以放多个 `.nbt` 变种，例如 `直道/直路1.nbt`、`直道/直路2.nbt`。权重是同一形状内部的相对权重：权重 8 对权重 1 表示前者被选中的机会约为后者的 8 倍，不代表保证每 9 段中有 8 段。选择由世界种子和道路区块坐标确定，通常不会在同一世界同一位置反复变化。某种形状没有任何 NBT 时，不会自动拿别的形状代替，日志会报告缺少目录/文件。

道路 NBT 的 X/Z 尺寸必须是 16 格的整数倍，且应与该阶段道路宽度及道路连接形状一致。多区块道路由一个 `.nbt` 作为整体跨区块放置；应按真实导出尺寸制作，不要将同一个大型道路文件拆成多份独立变种。道路文件里的方块状态会按道路连接方向旋转；方块实体/动态数据有单独恢复路径，但需在对应模组和新生成区块中验证。

### 地基处理

`城市范围内一律削平` 打开后，城市区块生成时会在 Lost Cities 放建筑前处理地基：清除城市地面及以上原有内容，对地面以下的空气/液体空洞补入地基材料，再让道路/建筑按自己的资源落位。当前地基处理仍有待办：岩浆湖残留或顶替、地面道路被原方块覆盖、道路下凹和洞穴钟乳石。此开关不能视为已彻底消除所有原版地物，也不能保证建筑/道路 NBT 本身没有空洞。

## 建筑文件制作与转换限制

建筑建议使用结构方块导出的 `.nbt`，每个文件代表一栋完整建筑，边界盒不要包含周围自然地面或隔壁建筑。导出前：

1. 将建筑门朝游戏南面；南侧是本项目识别的默认门面。
2. 明确建筑是否占满整区块。建筑占地与实际方块尺寸应一致，否则布局器按 NBT 边界盒预留的空地可能和肉眼建筑范围不符。
3. 检查边界盒中是否有 `structure_void`、空气、遗漏的底层、超出建筑本体的空白边界。道路稀疏 NBT 中的空气也会定义该道路场景的空白空间。
4. 对机械、容器、告示牌、实体和动态结构单独验收。数据能被 NBT 解析，不代表所有模组方块实体都能在生成阶段安全恢复。
5. 跨区块大型建筑应整体导出。Lost Cities 单格为 16×16 方块；建筑转换器按 16×16 的区块格切分，大于单格的建筑进入多格建筑资源。

转换器按 Lost Cities 的楼层模型将建筑垂直切片：每个非顶层切片高度为 6 格，剩余部分作为顶层。一个多格建筑的格子共享楼层信息和调色板；文件边界或高度不规则时，可能出现缺层、覆盖或调色板相关问题。超大建筑还受生成器多格矩阵最大尺寸限制，转换器常量为每轴最多 16 个区块格（理论边界 256×256 方块），实际是否能放入城市仍取决于城市尺寸和布局。

方块实体中的朝向/坐标、库存、Create 动态结构不能统一按普通方块状态看待。转换日志无报错只能说明文件被识别/转换；机器能否工作必须放入真实世界并在方块实体完成加载后测试。动态结构实体的开关位于 `附属功能设置.生成建筑自带的动态结构`。

## 常见测试与排错

### 指令找到城心，但现场没有城市

- 确认实例运行的是刚构建的 jar，而不是仅更新了源码或 `build/libs` 中另一个旧包。
- 城市搜索会重建附属的确定性候选计划；检查实际传送坐标、阶段范围、群系/高度和城市生成日志。计划城心不等于玩家已经加载过该区块。
- 若坐标附近只有原版地形，确认测试区块是新生成的；已生成区块不会回炉。
- 检查 `SpawnCityRule`、`CustomCityCenterPlanner`、`CityStageRuntime` 与城市中心/城市浓度相关 Mixin 是否使用一致的中心坐标。

### 某个阶段没出现或数量不符合预期

- 检查根配置 `阶段数量`、阶段 `启用`、距离最小/最大、风格目录是否加入 `可用城市风格文件夹`。
- 检查 `风格阶段生成.<风格>.<阶段>.是否生成` 是否开启，生成概率是否大于 0，随机风格模式下是否有有效可选风格。
- 检查中心高度范围、群系白名单、邻域地形检查和城心间距。大半径加较大最小间距会显著降低可放置中心数量。
- 数量上限是筛选候选中心用的；数量下限不会无视地形条件强行新增一个城市。
- `/cafcity all` 扫描 20000 格范围可能较慢。它在后台线程搜索，不应把等待误认成主线程卡死；同时查看日志中的搜索耗时和世界生成异常。

### 建筑没有生成、建筑太少或乡村留空

- 确认 NBT 放在风格/阶段/分区/`建筑文件/`，文件夹名与根配置完全一致；看启动日志中的扫描文件数、转换警告和错误。
- 对照 `/cafcity inspect` 返回的阶段、风格、分区和源文件名。建筑文件被读取不代表此分区一定能容纳其占地。
- 检查城市半径、分区大小、建筑宽深、连排限制、建筑间隔、同种间隔、逐建筑刷新率及数量上限。最少数量为 0 表示可选。
- 若打开空地填充仍有空地，检查该地块是否被道路占用、是否不能满足完整多格占地或连排矩形约束、是否达到数量上限。
- 做最小复现时先只留少量 1×1、1×2 建筑，清空复杂分区和过严的同款间距，再逐项恢复真实配置。

### 道路还是旧路面、地皮缺失或路面凹陷

- 确认 `.nbt` 在 `风格/阶段/道路文件/<形状>/`，且该形状文件夹有文件；建筑分区下的旧道路文件不会作为当前道路资源。
- 完全退出并重启游戏，确认根配置道路权重列表中的文件路径/文件名与磁盘一致。权重变化不是热更新。
- 看启动/生成日志是否出现“道路 NBT 已生效”及具体形状、文件名；如目录为空、NBT 尺寸不是 16 倍数或 NBT 解析失败，会有对应诊断。
- 检查 NBT 导出时的 Y 基准、底层高度、空气边界和 X/Z 尺寸。若所有道路都整体偏低，优先比较 NBT 内地面层相对原点与城市地面高度；若只缺局部，检查道路文件自身是否有空白或形状不匹配。
- 必须在道路连接方式匹配的场景里测试变种。旧区块里残留的平滑石/草方块等不能用于判断新代码仍在使用旧道路。

### 世界创建停在 0%、地形迟迟不加载或命令等待很久

- 记录世界创建时间、是否能进存档、CPU/内存状态，并复制完整 `logs/latest.log` 和对应崩溃/错误报告；仅凭进度条截图不能确定卡在哪个阶段。
- 先检查配置 JSON 是否有效、风格/阶段/建筑数量是否异常膨胀、NBT 是否过大或含复杂方块实体。配置转换发生在启动期，城心邻域地形检查也会额外采样。
- 对比禁用阶段系统前后日志中的启动、资源注册、Mixin 和世界生成时间；不要同时改多类配置，否则难以定位耗时源。
- 若命令已回复“正在后台搜索”，搜索仍在运行时再次输入会返回“已有城市搜索正在进行”。等待日志里的 `/cafcity 扫描` 耗时记录，不要连续发起大范围扫描。

## 开发者接手流程

交接者和 AI 建议按以下顺序工作：

1. `git status --short`：分清已有未提交更改与本次要做的改动；不要重置、覆盖或清理不属于自己的文件。
2. 打开实例实际使用的 `城市风格配置.json`，确认配置格式与源码模板一致。模板默认值不能代替用户的真实设置。
3. 从行为入口追调用链：命令查看 `mixin/CityCommandMixin` 和 `impl/CityCommandService`；城市规划看 `CustomCityCenterPlanner`、`CityStageRuntime`、`CityLayout`、`CityPlotPlan`；地基看 `CityFoundation` 和 `CityFoundationMixin`；道路看 `RoadNbtRuntime`；建筑资源转换看 `LcAssetGenerator` 与 `SchematicReader`。
4. 能先用 `tools/smoke/` 里的离线测试验证纯配置/布局逻辑；涉及真实 Lost Cities、NeoForge Mixin、方块更新或 Create 动态结构的行为仍需游戏内测试。
5. 一次只改一个生成因素，用新世界/新区域验收；记录世界种子、维度、城心、区块坐标、配置、源文件名、日志和预期/实际结果。
6. 验证通过后再更新此 README 的状态和待办，并明确哪些是代码测试通过、哪些是游戏内验证通过。

## 城市建筑朝向

建筑 NBT 的南侧（游戏坐标南，+Z）按设计视为建筑大门。朝向道路的实现会根据道路/建筑布局旋转建筑及其占地；其准确性目前仍在待办验收中。制作建筑时请保持门朝南导出，不要先把文件旋转成不同朝向；检查旋转问题时记录源 NBT、目标坐标、道路方位和建筑门的位置。

连排建筑要求同一条中的大门朝向一致；背靠背的两排可相向。近期实现还在验证南北和东西方向、宽度为 2 及以上的组合是否都能生成。

## 源码与构建

- `src/main/java/com/caf/lccustomcity/config/`：根配置、阶段/分区/道路/战利品解析及默认模板。
- `src/main/java/com/caf/lccustomcity/convert/`：建筑 NBT/兼容格式扫描、转换为 Lost Cities 数据资源，以及道路/战利品资源关联。
- `src/main/java/com/caf/lccustomcity/impl/`：城心候选、城市布局、地基、道路 NBT 和运行时服务。
- `src/main/java/com/caf/lccustomcity/mixin/`：接入 Lost Cities/Minecraft 生成逻辑和命令注册的 Mixin。
- `tools/smoke/` 与 `tools/stubs/`：离线 smoke test 和仅测试用桩类。
- `build.ps1`：当前受验证的本地构建入口（`build.bat` 调用它）；需要 JDK 21 和本机 Minecraft/Lost Cities 依赖路径，按 `local.properties.example` 配置 `local.properties`。不要提交含机器绝对路径的 `local.properties`、临时 classpath、测试输出或实例文件。

```bat
build.bat
```

构建产物写入 `build/libs/`。构建脚本负责编译和打包，不应把 jar 自动复制到某台机器的测试实例或个人归档目录。把源码交给别人时，先检查 `.gitignore` 和 `git status`，不要把个人实例、缓存和未确认的临时产物加入仓库。

修改生成代码后至少检查：

1. 构建成功，Mixin 与资源包均进入 jar。
2. 新世界能完成创建，出生点附近能正常加载地形和执行命令。
3. `/cafcity`、`inspect`、`find`、`all` 搜索到的城市阶段/风格/位置与实际生成一致。
4. 用新区域验证道路形状、变种权重、建筑数量/间距、朝向、地皮高度和分区覆盖。
5. 查 `logs/latest.log` 和崩溃报告，重点关注启动期配置扫描、Lost Cities 资源注册、Mixin 应用及区块生成异常。
